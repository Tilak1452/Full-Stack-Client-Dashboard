Key Design Decisions
Architectural choices and rationale
Auth
Supabase GoTrue
Zero custom auth code — JWT issued to browser, backend verifies via SUPABASE_JWT_SECRET; auto-detects HS256 & ES256
Database
Supabase PG
Cloud-hosted, shared across all developers; Session Pooler for DigitalOcean IPv4 compatibility
LLM routing
OpenRouter
Single key routes to Claude, GPT-4o, Gemini — automatic fallback; model swap = string change
Background jobs
APScheduler
In-process scheduler avoids Celery/Redis broker overhead for 2 simple 5-min polling jobs
Caching
Redis → dict fallback
Graceful degradation if Redis unreachable; in-memory is process-local and non-persistent
Vector store
ChromaDB / Pinecone
Abstract interface enables local-dev ChromaDB, prod Pinecone — zero code change needed
Migrations
Manual migrate.py
Idempotent ALTER TABLE IF NOT EXISTS; chosen over Alembic for simplicity (4 tables only)

Background Jobs (APScheduler)
Both run in-process · every 5 minutes
price_update_job — every 5 min
Batch-fetch all holding symbols via yFinance · update current_price, current_value, unrealized_pl on holdings · single DB transaction
alert_service job — every 5 min (300s)
Load all active alerts · fetch price/RSI/SMA per symbol · evaluate condition vs threshold · mark triggered + set triggered_at
⚠ Warning
Both run in-process. A blocking yFinance call on 50+ symbols could delay both jobs. No timeout per symbol fetch.
💼
Portfolio Transaction Flow
BUY / SELL / Summary
BUY — weighted avg price recalculated · holding upserted · Transaction record created (immutable)
SELL — quantity validated · FIFO P&L = qty × (price − avg_price) · holding qty reduced or deleted · Transaction with realized_pl created
Portfolio Summary — pre-computed by background job every 5 min · NOT recalculated on-demand
Note: "FIFO" in code actually uses weighted average cost basis — true FIFO tracks individual lots

CriticalHighMediumLow — Severity from architecture review
Critical
Sequential N+1 fetching on dashboard & stock pages
Dashboard fetches indices, movers, news, and per-symbol watchlist data in separate sequential useQuery calls. Backend has same pattern — no asyncio.gather() anywhere in services. On a watchlist of 10 stocks, that's 10 sequential HTTP round-trips, easily 10–15s total latency for Indian users.
Critical
Zero caching on stock data and LLM responses
Every /api/v1/stock/{symbol} call hits yFinance fresh. Redis is deployed but cache.py is never called by stock_service.py. LLM responses for identical queries are never cached — OpenRouter billed per token every time regardless of duplicate requests.
High
Mock data on core dashboard sections
Portfolio value area chart uses static portfolioHistory from mock.ts. AI insights cards use aiInsightsData from mock.ts — hardcoded content. Users with real portfolios see fake numbers on the main dashboard.
High
Watchlist not persisted server-side
localStorage only. Clearing browser data, opening on another device, or incognito mode = empty watchlist. No /api/v1/watchlist endpoint exists. Critical UX gap for a market dashboard users expect cross-device access.
High
CORS allow_origins=["*"] in production
Allows any domain to make cross-origin requests to the API. Combined with JWT auth this is partially mitigated, but it enables CSRF-style attacks and leaks the API's existence to malicious scanners.
High
pandas-datareader incompatible with pandas ≥ 3.0
macro_service.py silently returns hardcoded fallback values for 10Y Treasury, CPI, Unemployment. Dashboard shows stale static data (4.28%, 3.2%, 3.9%) as if live. No user-facing indicator that data is not real.
Medium
WebSocket stream has no authentication
WS /api/v1/stream/price/{symbol} accepts connections from anyone without a JWT. Risk is infrastructure abuse — bots could open thousands of connections and exhaust server resources. No connection limit or WS-level rate limiting.
Medium
Background job: no per-symbol timeout on yFinance calls
price_update_job.py batch-fetches all holding symbols. If Yahoo Finance hangs on one call, the entire job hangs, blocking both price update and alert check for that 5-min window. No asyncio.gather() with timeout, no circuit breaker.
Medium
Dual AI endpoints with overlapping purpose
POST /api/v1/analyze and POST /api/v1/agent/chat both do AI financial analysis. The frontend only uses /agent/chat. /analyze appears to be a legacy endpoint but is still registered, rate-limited, and uses AI tokens for nothing visible to users.
Low
Settings page has zero backend integration
The /settings page renders a form with no save functionality. Any settings change is lost on page reload. No user preferences are persisted anywhere.
Low
"FIFO" P&L is actually weighted average cost
SELL logic computes realized_pl = qty × (price - average_price) — weighted average cost basis, not true FIFO (which tracks individual lots). Documentation says FIFO. The mismatch could matter for tax reporting.
Ordered by impact-to-effort ratio. Start with the top items — each delivers visible user-facing improvement within a single session.
Priority 1 — Quick wins (hours each)
Add asyncio.gather() for parallel backend fetches
In stock_service.py and any route calling multiple services, replace sequential awaits with asyncio.gather(). On the dashboard route, fetch indices + movers + news concurrently. Estimated latency reduction: 60–80%. Zero API changes needed.
Priority 1 — Quick wins
Wire stock_service.py to the existing cache.py
cache.get/set is already built and Redis-connected. Add a 30s cache TTL to get_full_stock_data() and get_current_price(). Also add a 10-min cache on LLM responses keyed by (question_hash + market_session_date) — removes identical OpenRouter charges.
Priority 2 — High value (1–2 days each)
Replace mock dashboard data with live API calls
Portfolio chart: call GET /portfolios/{id}/summary and plot current_value. AI insights cards: call /api/v1/agent/chat with 3 pre-set prompt templates on page load, cache results for the session. This is the #1 visible UX gap — fake data on the main screen.
Priority 2 — High value
Add server-side watchlist persistence
Add a watchlist table (user_id, symbol, added_at) + CRUD endpoints GET/POST/DELETE /api/v1/watchlist. Migrate from localStorage on first load. Keep localStorage as offline fallback. Single-session effort, high user retention impact.
Priority 3 — Security & reliability
Lock CORS to production domain
Change allow_origins=["*"] to allow_origins=[settings.frontend_url] where FRONTEND_URL is set in .env. Add to .env.example and DigitalOcean env vars. 5-minute change, significant security improvement.
Priority 3
Fix pandas-datareader / replace with direct FRED API
Either pin pandas<3.0 in requirements.txt (quick, tech debt) OR replace pandas_datareader with direct FRED REST API calls using httpx. FRED API is free and returns JSON — no pandas dependency needed. Add UI indicator when macro data is from fallback.
Priority 3
Add WS connection auth + rate limiting
Accept an optional ?token=... query param on the WS endpoint. Verify it on connect (same decode_access_token logic). Add a max-connections-per-IP counter using the existing cache layer. Prevents resource exhaustion from bot connections.
Priority 4 — Low effort cleanup
Add per-symbol timeout to price_update_job
Wrap each symbol fetch in asyncio.wait_for(..., timeout=5.0). Any symbol that times out logs a warning and is skipped — other symbols still update. Prevents one bad ticker from blocking the entire 5-min job window.
